# 程序打包 · 第一阶段使用与维护

更新：2026-10-04。入口：`/tools/python-package`，分类为“开发辅助”。

> 本文保存第一阶段的历史验收与操作记录。当前管理入口、私人凭证模式和公共隔离模式以《网站交接文档.md》§15 为准；下文的仅限 localhost 流程属于历史版本。

## 1. 当前交付范围

- Python 项目生成 Windows x64 程序；目标 Windows 10/11，需在客户电脑上验证。
- 输入支持单个 .py、多文件、文件夹和 ZIP。拖拽、选择、浏览器能取得的剪贴板文件共用项目列表；文件夹或 ZIP 的单层共同外壳目录会被移除，请确认列表中的相对路径。
- 选择入口、已准备的 Python 环境、程序名称、命令行/窗口模式、单 EXE/文件夹 ZIP。读取 requirements.txt 后可编辑；资源可勾选，ICO 和动态导入模块可选。
- 单任务构建，其余排队；日志、取消、下载、删除，以及任务凭证的保存与导入恢复。
- 当前实际准备并验证的是 Python 3.12.14 x64 + PyInstaller 6.16.0。网页只列出已准备环境；并不承诺所有 Python 版本或任意项目都能打包。

第一阶段只供网站所在电脑通过 localhost 或 127.0.0.1 试用可信项目。穿透请求被拒绝。管理页面、登录和公共服务开关尚未实现；第二阶段的开关将首次关闭并持久保存、开启后对全部访客共享。

## 2. 启动

项目当前 Node 24.19 可直接执行 .mts 脚本。网站按原有方式启动；打包 Worker 是单独的终端进程，网站重启不会代替它的启动。

首次准备或增加环境，在项目根目录运行：

```powershell
npm run packager:prepare -- --python "C:\你的Python安装目录\python.exe"
```

要求 Windows 上的 Python 3.8+ x64，带 venv/ensurepip。建议选择稳定安装的 Python 3.12。准备过程仅建立项目专用环境，固定安装 PyInstaller 及构建组件，不修改系统 Python。下载来源为 PyPI，需要网络；运行成功才写入环境配置。

本次已使用本机现有的 Codex 配套 Python 3.12 准备环境，其路径在 `private/packager/config.json` 中。如果以后 Codex 更新导致路径失效，请用自己的 Python 安装路径重新执行准备命令。原有 Python 3.8 的准备没有成功，未登记为可用环境。

启动任务服务：

```powershell
npm run packager:worker
```

在本机浏览器打开网站的 `/tools/python-package`，点击“刷新服务状态”。Worker 终端按 Ctrl+C 可停止；只会取消它自己的构建子进程。不要同时启动两个 Worker。

生产网站需要用户自行 `npm run build` 并重新启动才显示新增工具；本次开发没有重启用户的网站或隧道。

## 3. 打包步骤

1. 添加项目文件。不要包含 .git、venv/.venv、缓存、node_modules、真实 .env、.pem/.key 文件；遇到这些路径会拒绝项目，不会读取这些文件做配置。
2. 确认启动入口；默认优先 main.py。多文件项目必须带上被导入的代码文件。
3. 确认 Python 版本及第三方依赖。仅支持 PyPI wheel，包名、版本约束和有限的环境标记；不支持网址、本地路径、任意 pip 参数、源码编译依赖或替换 PyInstaller。
4. 勾选需要随程序携带的资源。项目内相对路径保持；代码宜使用 `Path(__file__)` 定位资源，依赖当前工作目录的代码需要自行调整。外部数据库、驱动、网络服务和客户文件不会自动打包。
5. 选择命令行或窗口模式。窗口模式只隐藏终端，不会给脚本自动生成图形界面。选择单文件或文件夹输出；文件夹 ZIP 下载后应完整解压，再打开其中的 EXE。
6. 提交后在任务区域观察日志。离开页面前可下载任务凭证 JSON，再导入恢复。凭证包含任务访问权，勿分享；网站不把项目或凭证写入 LocalStorage。
7. 下载后在客户电脑试运行；单文件会先解包，需要可写临时目录。失败时查看日志，必要时尝试文件夹输出。确认完成后可手动删除任务文件。

## 4. 保存与限制

任务目录：`private/packager/jobs/<UUID>`；包含项目、独立 venv、构建缓存、结果和日志。目录被 Git 忽略，不位于 public，不应作为静态文件公开。生产构建也不会追踪打包任务数据。`build/` 中的本次验证数据属于忽略目录，未复制真实环境文件。

| 项目 | 限制 |
| --- | --- |
| 项目展开后总大小 | 50 MiB |
| 项目文件数 | 1000 |
| 单个结果 | 500 MiB |
| 单任务整体目录 | 超过 2 GiB 时请求终止；检查每 2 秒进行，可能短暂超出 |
| 单任务时间 | 20 分钟 |
| 未完成任务 | 最多 10 个，含当前任务 |
| 保留任务 | 最多 30 个 |
| 日志 | 保留末尾 128000 字符 |
| 保留时间 | 提交起 24 小时 |

到期凭证立即无效；Worker 每分钟清理已结束的过期任务。Worker 停止期间不会清理磁盘，恢复后补清理。构建组件和环境配置长期保留，任务的 venv/缓存随整个任务到期或手动删除。

配置为解释器路径和 wheelhouse，不放真实密码。`state.json` 目前仅预留 `enabled: false`，不控制本机试用服务，也没有管理员密码。

## 5. 中断与残留锁

任务状态写入磁盘，重新启动 Worker 后，排队任务继续排队；上次正在准备/安装/构建的任务会标记失败，可凭原凭证查询并重新提交。网站重启或刷新不会自动恢复浏览器内的任务列表，需要导入此前保存的凭证。

正常 Ctrl+C 会清理 Worker 锁和心跳。强制结束、断电可能留下 `worker.lock`；上传进程异常可能留下 `submit.lock`。必须先核对相应进程确实已结束，再只删除对应残留锁；不要根据文件存在就终止未知 Node、网站或隧道进程。无法确认时保留文件并排查。

## 6. 安全与验证边界

venv 隔离依赖，**不是安全沙箱**。第三方 PyInstaller hook 等构建步骤可能执行代码，构建进程仍具有当前 Windows 用户的文件权限；因此本阶段只处理可信项目，不接受未知公网项目。项目不会发送给第三方构建平台，依赖下载只访问 PyPI；构建子进程使用最小环境，不继承网站密钥或 Python 用户配置。提供路径、体积、数量、依赖语法和任务凭证检查，拒绝穿透/跨站请求。下载凭证经 POST 提交，不放入 URL。

本次实际验证记录见《网站交接文档.md》§13。尚未在一台没有安装 Python 的客户电脑上验收，不能用本机 PATH 移除 Python 的测试代替该验收；真实手机、系统文件管理器复制/拖拽和自定义图标还需要实际操作验证。
