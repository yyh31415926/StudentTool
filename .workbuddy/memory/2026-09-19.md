## 完成：StudentTool 产品设计评审文档

**产出**：`Design/WorkBuddy_Design_Review.md`（新建，约 400 行）

**输入依据**：`Documents/WebsiteDesignDocument.md` v0.1

**评审核心结论**：
- 方向成立（学生向工具站 + 二次元体验是真实空白位），但定位需收敛
- 最大风险 R1：工具集合不是产品，用户无回访理由（对手是浏览器地址栏而非其他工具站）
- 第二批问题：工具与画像错配（Base64/JSON/Markdown 对高中生零价值）、分类维度不统一、首页模块过多

**给出的关键建议**：
1. 定位收敛：高中生为主 + 三个具体场景（写作业 / 信息课 / 自习整理）
2. 分类重做：3 类（转换工具 / 文本处理 / 开发辅助），引入 tag 作为第二维度；空分类不渲染
3. 首页瘦身：搜索 + 分类 + 常用工具 + 我的工具箱 四个功能区；搜索框为第一优先级元素（即时下拉）
4. 角色设计：5 个允许位置（空状态优先级最高）+ 4 个禁区；量化约束（工具页角色 ≤15% 面积、操作区周围 0 装饰、动画 ≤300ms）
5. MVP：6 个工具做到零缺陷优于 20 个半成品；工具页做 SEO 长尾入口
6. 商业化红线：只卖外观不锁功能

**发现的文档不一致（12 条，已列入评审 §7）**：
- §10.3 引用 `AGENT_RULES.md`，但该文件在当前工作空间中不存在

- §5.2「学习工具」与「数学/编程工具」不在同一分类维度

## 完成：项目正式设计文档 v0.2

**产出**：`Documents/WebsiteDesignDocument_v0.2.md`（新建，约 700 行）

**已由用户拍板并写入 v0.2 的决策**：
- 定位：属于学生的数字工具工作台；高中生主要、大学生次要
- 工具优先级：P0 单位换算 / 字数统计 / 进制转换；P1 Markdown预览 / JSON格式化；P2 Base64；**Hash 降为 P3 暂缓**
- 分类：转换工具(convert) / 文本处理(text) / 开发辅助(dev)，**2-2-2 均衡分布**
- 首页：顶栏 + Hero(搜索) + 分类入口 + 常用工具 + 我的工具箱，共 4 个功能区
- 角色：品牌形象 / 页面装饰 / 情绪反馈；禁止对话气泡、主动指导、聊天功能

- 技术：Next.js + React + Tailwind + LocalStorage；未来 PWA/App

**v0.2 中由我做出的主动判断（非盲目采纳评审，已在 §0.4 记录）**：
- ❌ 不做标签筛选 UI（6 个工具时交互成本 > 收益），但 tags 字段保留用于搜索
- ❌ 不提供"清空我的数据"按钮（无账号下误触不可恢复），仅做文字说明
- ❌ v1 严格不引入文件上传类工具（图片/PDF），限定为纯文本与数值类
- 🔶 "继续上次"合并进"我的工具箱"首行，但要求该模块必须在首屏可见范围内
- 🔶 Base64 从评审的"转换工具"微调至"开发辅助"（2-2-2 均衡 + 使用者画像 + 与 v0.1 归类连续）
- 🔶 单位换算用自定义界面，不强套通用模板
- ✅ 暗色模式：亮/暗双 token + 跟随系统、不做切换器；明确界定「暗色模式 ≠ 多主题系统」
- ✅ 搜索支持拼音首字母（jz → 进制转换），纳入 v1
- ✅ 定案"最近使用"判定条件 = 产生有效输出或点击操作按钮（打开页面不算）
