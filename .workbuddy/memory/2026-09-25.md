## 修复「复制二维码图片」非安全上下文兜底

- 问题：HTTP 局域网（`http://YYH:3000` / `http://局域网IP:3000`）下浏览器因非安全上下文拒绝图片剪贴板。
- 修复（`src/components/tools/custom/qrcode/QRCodeDownloadActions.tsx`）：
  - 新增 `supportsImageClipboard()`，复制前四重检测：`window.isSecureContext`、`navigator.clipboard`、`navigator.clipboard.write`、`ClipboardItem`（= window.ClipboardItem）。
  - 支持时：SVG→PNG Blob→`ClipboardItem` 写入 `image/png`，成功提示「二维码图片已复制到剪贴板」。
  - 不支持或被拒时：自动 `fallbackDownloadPng()` 下载 PNG 兜底，提示「当前浏览器或 HTTP 局域网环境不支持直接复制图片，已自动下载 PNG 文件。」（不再只报「操作失败」）。
  - 复制按钮在无内容时仍禁用，有内容时始终可用（不因不支持而禁用）。
  - 不改变「下载 PNG」「下载 SVG」行为。
- 验证：tsc 通过、eslint 0 错误、测试 222/222 通过（组件无单测）。
- 遗留观察：全站 `text-error` 语义色在 globals.css 的 token 中未定义（既有工具同样在用，属历史遗留，未在本次处理）。

## 新增「图片文字识别」image-ocr

- **工具 id**：`image-ocr`，名称「图片文字识别」，分类 `text`，order 9，`customUI: "image-ocr"`。
- **功能**：选择 / 拖拽 / 粘贴图片（PNG·JPG/JPEG·WebP，单张 ≤10MB，最长边 >8192px 报错，识别前缩到长边 ≤2500px）→ 选择语言（简体中文 chi_sim / 英文 eng / 中英混合 chi_sim+eng，默认中英混合）→ 本地 OCR → 复制结果。图片只在浏览器本地处理，不上传。
- **依赖**：`tesseract.js@7.0.0`（仅识别时动态 `import()` 懒加载；模型权重默认从 CDN 加载，属已知限制，正式上线前可改自托管）。
- **架构决策**：沿用 qrcode 的 `customUI` 机制（模板 ≤5 红线不变），未新增模板；纯函数核心 `src/lib/tools/image-ocr.ts`（图片类型/大小/尺寸校验、语言归一化、缩放计算、`run` 入口），真正的 OCR 异步逻辑在 `custom/image-ocr/ImageOcrTool.tsx`。
- **新增文件**：`src/lib/tools/image-ocr.ts`、`src/lib/tools/definitions/image-ocr.ts`、`src/components/tools/custom/image-ocr/ImageOcrTool.tsx`、`tests/tools/image-ocr.test.ts`（27 组）。
- **修改文件**：`src/lib/tools/definitions/index.ts`、`src/components/tools/custom/registry.tsx`、`tests/tools/categories-data.test.ts`（text 快照 1→2）。
- **验证**：测试 249/249 通过；`tsc --noEmit` 通过；`eslint` 0 错误；生产构建 17/17 静态页（含 /tools/image-ocr，此前 16 页）通过。
- **未验证**：真实 OCR 识别准确率（需浏览器真机实测，测试环境无）；tesseract.js CDN 在中国大陆的可达性；真机移动端布局与软键盘遮挡；带 EXIF 旋转的 JPG 识别。
- **备注**：本工具属「文件上传类（图片处理）」工具，落在 v0.2 §6.2 / AGENT_RULES §2.2、§9.2 的 v1 禁止范围内；按用户明确指令（本地 OCR、不上传、不接 API、不接摄像头）视为对上述红线的明确豁免执行。

## 图片文字识别 image-ocr 增加「DeepSeek 识别」模式

- **目标**：在既有 OCR 工具上增加可选识别方式——本地识别（默认）/ DeepSeek 识别（用户主动切换才上传）。切换不丢图片、不自动识别、不自动重试、失败保留原输出。
- **模型与端点**：`deepseek-flash`（DeepSeek-V4.1-Flash，官方当前支持图片输入的模型 ID；用户口述 `deepseek-v41flash` 即此）→ `POST https://api.deepseek.com/chat/completions`（OpenAI 兼容，`image_url` + base64 data URL 内联）。
- **架构**（项目首个服务端 API 路由，突破此前「纯前端」假设）：
  - `src/lib/ocr/deepseek.ts`：服务端封装。用 `process.env["DEEPSEEK_API_KEY"]`（方括号访问避免构建期内联，保证运行时配置生效），绝不用 `NEXT_PUBLIC_`、绝不进前端。含 `parseDataUrl`/`normalizeImageDataUrl`/`extractText`/`callDeepSeekOcr` 等纯函数 + `DeepSeekError`（带状态码）。
  - `src/app/api/ocr/deepseek/route.ts`：`GET` 返回 `{configured}`（不泄露密钥）；`POST` 校验图片（类型/大小/非空，复用 `src/lib/tools/image-ocr` 共享常量）→ 调 DeepSeek → 只返回 `{text}`。`runtime=nodejs`、`dynamic=force-dynamic`、`maxDuration=60`。不写磁盘、不保存图片/结果、不泄露上游错误与密钥。
  - `ImageOcrTool.tsx`：新增 mode（local/deepseek）+ 隐私费用提示 + DeepSeek 九态（uploading/recognizing/success/empty/not-configured/timeout/network-error/api-error）+ AbortController 超时/取消。
- **其它改动**：`globals.css` 补 `--color-error`/`--color-warning` 语义色（此前 `text-error` 是空操作的历史遗留）；`vitest.config.ts` 补 `@`→`src` 别名（此前测试从未经 `@/` 做值导入，未暴露）；新增 `.env.example`（`DEEPSEEK_API_KEY=`）+ `.gitignore` 放行 `!.env.example`；`tests/ocr/deepseek.test.ts`（21 组）。
- **安全**：Key 仅服务端读取、不进前端/localStorage、不返回浏览器；未配置时前端显示「管理员尚未配置 DeepSeek API Key」并禁用按钮；请求体 Content-Length + base64 大小双重限制。
- **验证**：`tsc` 通过、`eslint` 0 错误、测试 270/270 通过、生产构建通过（17/17 静态页 + `ƒ /api/ocr/deepseek` 动态路由）；`git status` 确认 `.env.local` 被忽略、`.env.example` 会被跟踪。
- **未验证**：真实 DeepSeek 识别效果（无 API Key，需本机配 `.env.local` 后实测）；中国大陆到 api.deepseek.com 的网络可达性；移动端真机。
- **备注**：本改动引入服务端 API + 第三方 DeepSeek 调用、且 DeepSeek 模式会上传图片，落在 AGENT_RULES §3.1「禁止后端服务」与 §2.2/§6.2「禁止上传用户数据」红线内；按用户明确指令（用户主动选择才上传、Key 仅服务端、隐私/费用提示）视为对上述红线的明确豁免执行。

## image-ocr 输出区改为可编辑 textarea

- 把识别结果输出从只读 `<pre>` 改为受控 `<textarea>`（`value={result}` + `onChange` 回写），本地/DeepSeek 结果都写入同一个 `result` 状态；复制按钮本就读取 `result`，因此复制的是含手动修改后的当前内容。
- 新增 `confirmOverwrite()`：重新识别前若 `result` 非空则 `window.confirm("当前已有识别结果，重新识别将覆盖它。是否继续？")`，取消则直接 return（保留当前内容）；本地与 DeepSeek 两个识别入口都调用。识别失败仍保留原输出（原逻辑不变）。
- 仅改 `src/components/tools/custom/image-ocr/ImageOcrTool.tsx` 一个文件；输出区说明文字改为「可直接编辑、复制」。
- 验证：tsc / eslint / 270 测试 / 生产构建均通过。
